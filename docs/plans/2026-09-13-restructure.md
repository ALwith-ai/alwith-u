# ALwith U：WorkBuddy 参考应用实施计划

更新：2026-09-15。状态：底座重构及本地发行验证推进中，完整产品验收未完成。目标以 [WorkBuddy 职责边界](../workbuddy.md) 为准。

## 取代旧要求

| 删除的要求 | 当前要求与原因 |
| --- | --- |
| 唯一共享 Runtime，不提供客户端包 | 提供协议、客户端与复杂交互成品，避免每个用户重写通用能力 |
| 强制把客户端并入 src/runtime、删除 packages | 按实际复用边界决定目录，不因名字或“不要 SDK”而复制实现 |
| 全部在 TS、Rust 只剩 relay 与窗口 | UI 技术自由，TS／Rust 按实际能力分工 |
| 删除 in-process fake，所有测试起二进制 | 保留仓库单元测试约定，真实协议验收另设 |
| 只钉最低版本，应用自动跟随 Runtime 升级 | 保留现有发行版本锁定；兼容与升级策略经验证另定 |
| 必须 U 改写 U，首个任务必须自建同步 | 用户可用任意编程 Agent；U 是参考，不是唯一制作入口；平台服务不甩给用户重建 |

generate-ts 等生成机制不是已实现结论；执行器扩展类型不无依据交给 Runtime 生成。当前 U 使用独立 `@alwith/api` 包和 stdio 宿主路径；本地发行物已做独立消费验证，公开获取与许可仍待决定。

## 不改变的边界

- 依赖验收按 [Rust 依赖与进程边界](../workbuddy.md#rust-依赖与进程边界)：不要求 Desktop 清空 alwith-dev 编译依赖；QA 的能力独立不强制拆 crate 或进程。检查具体调用是否重复运行、绕过 Agent 托管或泄露私有实现，而不是按名称删依赖。

- 产品名 ALwith U；本仓是 Codex 客户端，不另造原生会话权威库。
- U 的文件树、浏览器等既有排除项不因平台范围扩大自动启用。
- 本仓自身仍遵循 shadcn 约定，不强制其他用户应用使用。
- 会话同步仅涉及记录，历史查看与原生续聊分别验收。
- 保留在途工作；底座改动按用户后续重构授权实施，不选择许可证、不发布、不提交或推送。
